# Sun 0.1 architecture

## Current execution model

source -> lexer -> parser -> AST -> interpreter/runtime

Native execution currently follows:

source -> lexer -> parser -> AST -> LLVM IR -> native executable

Semantic analysis and a stable Sun IR remain planned layers between the AST and LLVM.

Native scalar math calls cross a C ABI bundled into each executable (`runtime/sun_runtime.c`). The runtime now also provides an opaque heap-backed `SunMatrix` ABI with 1-based access, shape queries, arithmetic operations, and explicit ownership. The LLVM generator uses the heap-backed matrix ABI. The numeric crate also exposes borrowed, read-only matrix views for rectangular regions and transposition; these views retain the source allocation through Rust lifetimes and do not copy element data.

## Initial decisions

- Rust workspace with independently testable crates.
- Dense f64 matrices for the first release.
- Public matrix indexing is 1-based.
- LLVM is the native backend; the CLI invokes Clang 18+ to compile generated LLVM IR.
- The interpreter supports numeric expressions, variables, matrix literals, matrix addition and element-wise multiplication with 2D singleton-dimension broadcasting, matrix multiplication, scalar multiplication/division, 1-based matrix reads via `A(row, column)`, and basic math functions, materialized transpose, determinant, inverse, and linear-system solving (`solve(A, B)`) using partial-pivoting Gaussian elimination.
- The LLVM backend supports scalar arithmetic, fixed-shape dense matrix literals/operations, matrix display, compile-time literal 1-based matrix reads, and native math calls through the C runtime ABI.
- A trailing semicolon suppresses the implicit result; `disp(...)` still writes output.
- The interpreter executes `while ... end` and `if ... elseif ... else ... end` blocks with a shared variable environment and boolean or finite scalar numeric conditions. Zero is false; nonzero is true. Conditions are re-evaluated before each loop iteration, and only the first matching conditional branch executes. Logical `&&` and `||` short-circuit and use the same scalar condition rules. `Value::Bool` is distinct from `Number`; boolean literals, comparisons, logical operations and `isempty` produce it. Numeric operations explicitly convert scalar booleans to 0/1; matrices remain f64 rather than logical arrays.
- The parser shares block parsing across modules, loops, and conditional branches. It validates loop context for `break` and `continue`, including in unexecuted branches. Block closing keywords belong to the nearest matching construct.
- Execution propagates `Normal`, `Break`, `Continue`, and `Return` separately from runtime errors. Conditionals and switches forward control flow; the innermost `for` or `while` consumes `Break` and `Continue` but forwards `Return`. Script and function executors consume `Return` as successful termination while preserving earlier output. Return takes no expression; functions return their named output variable. Native return compilation remains future work.
- The interpreter supports `for variable = start[:step]:stop` with finite scalar bounds evaluated once. The default step is 1; zero steps are errors. Numeric ranges generate values by iteration index using fused multiply-add, with a bounded quotient-relative rounding tolerance at endpoints, without materializing vectors in loop headers. Iteration indices must fit the exact integer range of `f64`, and repeated iteration values are rejected. Empty ranges do not assign the variable. The same `IndexRange` AST form materializes row vectors in ordinary expressions, with arithmetic above colon above comparisons in precedence. Index-context ranges keep stricter integer/bounds validation. Native ranges and control flow remain future work.
- A separate `ForEach` AST form represents `for variable = source` without a colon. The interpreter evaluates the numeric source once, retains an owned snapshot, and iterates its columns using the existing matrix view API. Row-vector columns become numbers; multirow columns become independent matrices. Scalar sources iterate once. All zero-element sources skip the body without assigning the loop variable, including `0xN` matrices. Both for forms consume loop control identically and are rejected explicitly by the native backend.
- MATLAB-style comments begin with %.
- `ParFor` is a separate AST form for integer ranges with step +/-1. The runtime's parallel module performs conservative structural analysis before script execution; the CLI also invokes it for `check`. It classifies fresh, definitely assigned temporaries, read-only broadcast inputs, and write-only output matrices indexed directly by the iteration variable with an optional fixed axis. Effects, reductions, nested control blocks and inconsistent output patterns are rejected.
- Rayon executes worker partitions with independent local environments. Input bindings are copied once per partition, while expression evaluation borrows matrix data for scalar reads. Workers stage numeric scalar writes; the main execution environment is updated only after all workers succeed. Binding and bounds preflight prevents invalid output writes, and failures preserve every output. Temporaries and the iteration variable do not escape into the outer environment. Native parallel lowering and richer dependence analysis remain future work.
- `IndexEnd` represents `end` used in argument expressions, separately from block delimiters. Scalar and slice matrix reads and assignments evaluate each index under a temporary dimension context: element count for one index, rows/columns for two. Nested indices override and restore it, including on errors. Ordinary function arguments within an index inherit its dimension. Assignment values use their own context. Index validation remains shared for reads and writes. Growth and native index-end code generation remain future work.
- Linear slice selection reuses `IndexAll`/`IndexRange` with the total element count as its dimension. `select_linear` always creates a column for `:`, preserves vector orientation for ranges, and creates a row for ranges on matrices. `fill_linear_selection` and `assign_linear_selection` validate all indices before writing. Linear RHS matrices need matching element count rather than matching shape and are read by columns. The target shape is preserved, and overlapping writes use an evaluated RHS snapshot. Empty selections produce shaped empty values and accept scalar or empty writes as no-ops.
- `IndexAll` and contextually interpreted `IndexRange` represent direct index selectors. Bidimensional slice reads and writes evaluate finite integer bounds in the corresponding axis context and reuse the numeric progression machinery. Endpoints are validated before materializing index lists. Other index expressions are evaluated once under their axis context and classified as scalar or numeric vector, independent of syntax. `SunMatrix::select` validates coordinates and output size before creating an independent ndarray-backed matrix. Scalar-only reads remain numbers; vector/selector reads remain matrices. Empty selectors preserve the other axis dimensions, whose nonempty indices remain validated.
- Runtime numeric built-ins live in `numeric.rs`. Constructors use shape-aware checked allocation; matrix concatenation delegates to ndarray along each axis. Mean/min/max reduce all elements like the existing sum; empty mean is NaN and empty min/max are 0x0. Pairwise min/max use the shared singleton broadcasting path and propagate NaN. Elementary scalar functions map matrices without shape changes. Constructor, range, concatenation, selection, multiplication and broadcast result sizes are checked against a 16,777,216-element/dimension limit, including zero-dimensional operands. This is a per-result bound, not a global memory quota.
- `SunMatrix` accepts zero dimensions: `[]` constructs `0x0`, and selections construct `0xN` or `Nx0`. Shape-preserving operations use ndarray rather than round-tripping through row vectors, which cannot encode column count when there are no rows. Singleton broadcasting propagates a compatible zero dimension instead of using its maximum with one. Empty sums, products, transpose, and compatible linear algebra have defined shapes; determinant of `0x0` is one. Numeric `size`, `numel`, and `isempty` expose shape information. Empty assignments do not imply deletion or growth; native empty support remains future work.
- `fill_selection` and `assign_selection` share complete coordinate validation with reads. Slice writes expand scalars or require an exact matrix shape, and validate before mutating any destination element. The interpreter evaluates RHS values before borrowing the target mutably, making overlapping self-assignments safe. Shape, bounds, type or evaluation failures do not partially update the target; earlier expression side effects are not rolled back. Native slice writes remain unsupported.
- `SunMatrix` owns the 1-based column-major mapping used by `get_linear` and `set_linear`, independently of its ndarray storage order. Linear bounds failures carry index and element count and map to the existing `Sun:IndexOutOfBounds` identifier. `LinearIndexAssign` represents scalar single-index writes without changing the existing bidimensional AST form. Reads use the shared call/index syntax; both linear forms are currently interpreter-only.
- Runtime effects are supplied through `RuntimeHost`: output lines, typed figure events, timed pauses, optional interactive input, file readers and atomic file writes. Default file methods use regular filesystem files; embedded hosts can deny or replace them. Graphical hosts override `figure_event`; the default reports unsupported graphical output rather than ignoring it. `execute_with_host` runs with injected effects; the existing `execute` adapter collects lines while retaining real timed pause behavior. Hosts without input support report an I/O error for enabled interactive waits. The CLI writes and flushes each line before continuing. Tests record effects without wall-clock waits or human input. Host I/O failures map to `Sun:IOError`.
- `graphics.rs` owns one active figure per session and validates plotting commands, numeric vectors/matrix columns, labels, legend cardinality, grid and increasing axis limits. Figure creation emits data once; metadata changes emit only layout. Explicit axis changes increment an axis revision, separate from figure ID, so Plotly can reset bounds without losing zoom on unrelated metadata edits. Figures support up to 16 traces and 10,000 total points; nonfinite coordinates are encoded as nullable gaps and each curve requires finite data. Plotting built-ins are output-less effects and excluded from parfor. Default text hosts and LLVM report graphical-host guidance. Session clear discards figure state.
- `matrix_csv.rs` implements `readmatrix`/`writematrix` using the Rust csv crate without headers, with explicit numeric conversion and row-major shape validation. A cancellation-aware input adapter validates quote structure, strips even fragmented BOMs, and caps files at 64 MiB, records at 1 MiB and columns at 65,536 before the parser can expand unbounded field buffers. Numeric values accumulate in one fallibly grown buffer consumed by `SunMatrix::from_row_major`; matrix limits apply before allocation. Output uses a bounded csv writer and validates the same record/column limits before the host sees any contents. The default host writes a same-directory temporary file, preserves existing regular-file permissions, syncs and renames only after cancellation checks. Symlink/special-file destinations are rejected; new files retain private temporary-file permissions. Empty CSV maps to 0x0; other empty matrix shapes are not exportable without losing shape. Malformed data raises `Sun:InvalidCSV`, and filesystem errors remain `Sun:IOError`. These are effects, forbidden in parallel headers/bodies and unsupported by LLVM. Scripts remain trusted filesystem clients, not sandboxed by Studio's renderer file grants.
- `Session` owns variables, an immutable-during-execution registry of shared function definitions, and an initially enabled pause flag across commands. `execute` validates the module, registers definitions, then runs only the supplied statements; `clear` resets all session state. Runtime errors and script returns preserve earlier assignments and registered definitions. Compatibility execution APIs create fresh sessions. `ExecutionContext` temporarily carries host effects, index dimensions, function registry/depth and cancellation state. `pause("on"/"off")` returns the previous state; `pause("query")` returns the current state. Disabled pauses skip host waits but still validate arguments. `pause(seconds)` accepts finite nonnegative `Duration` values, and `pause()` or an unbound bare `pause` requests interactive input.
- `FunctionDefinition` stores a name, unique parameters, an optional output name and body. The parser permits declarations only at module level and rejects duplicate module definitions. Calls bind owned argument values in a fresh local environment with no caller-variable access. Function entry clears index-end context and restores it and call depth on success or error; pause state, host and cancellation are shared. Named outputs are required, and output-less calls are permitted only as statements. Self/mutual recursion is bounded to 32 calls and produces a catchable error rather than unbounded native recursion. Declarations are available for forward calls and persist between session commands; redefinition replaces the prior definition. Parallel validation traverses function bodies, and parallel execution rejects calls to user functions, including shadowed pure built-ins, before worker effects or output commits. LLVM rejects function declarations explicitly.
- The CLI REPL buffers incomplete blocks and executes each complete module once in its session. It uses Crossterm for terminal key events with a raw-mode restoration guard, and buffered line input for pipes. Ctrl+C during a key wait reports interrupted I/O, and EOF in a pipe reports unexpected EOF. Native pause compilation remains future work.
- Hosts may expose an atomic cancellation flag. Statement boundaries, loop bodies and parallel workers check it; cancellation bypasses `catch` and preserves completed sequential assignments. Parallel outputs are committed only after successful workers and a final cancellation check. Individual numerical operations are not generally interruptible.
- Studio owns one lazy `sun studio-session` process. Protocol v2 carries source in JSON commands and correlates output, diagnostics, input, Workspace and figure events with job IDs. Figure events are `figure` (complete traces/layout), `figure_update` (figureId/layout) and `figures_cleared`. Workspace `hasFigure` preserves discard confirmation even for a figure-only session. CLI hosts serialize the same typed Rust models; main-process validation enforces finite/nullable bounded data and metadata before forwarding. Reset and session loss explicitly clear renderer figures. A stdin reader thread routes jobs and cancellation/input controls separately, allowing timed or interactive waits to stop without discarding the session. Checks do not execute code or change its working directory. Reset clears the runtime session without replay. Forced termination, engine replacement and application shutdown discard the in-memory session explicitly. Legacy `sun studio FILE` protocol v1 remains available for isolated execution, including figure events.
- The renderer dynamically loads locally bundled plotly.js-basic-dist-min only for a figure. FigureView coalesces asynchronous updates, resizes through ResizeObserver, ignores hidden zero-sized containers and purges Plotly state on unmount. Presentation maps Rust data/layout without interpreting Sun, escapes text markup, uses revision keys for interactive state, and reserves separate title/tool/axis/legend areas. Tables and Details remain available alongside the Graph tab. Browser interactions change presentation only; script commands remain controlled by Rust.
- The interpreter supports `try ... catch [name] ... end` with a required handler and optional exception variable. Only `RuntimeError` results enter catch; normal execution and `Return`/`Break`/`Continue` flow bypass it. Both bodies share the existing environment and output, without rollback. Handler errors propagate outward.
- `SunException` values carry an identifier and message, exposed through read-only `FieldAccess` expressions. Built-in errors map to stable `Sun:...` identifiers; `error(message)` or `error(identifier, message)` creates an exception. `rethrow(exception)` preserves both fields without adding formatting prefixes. Named handlers assign their exception variable only on failure and do not create a separate scope. Stack traces, causes, MATLAB-style formatting and native exception handling remain future work.
- The interpreter evaluates a `switch` selector once and evaluates boolean, numeric or string case expressions sequentially until the first exact, same-type match. Only that body executes, with an optional final `otherwise` when no case matches. There is no fall-through. Switch blocks forward loop control rather than consume it. Matrices, cell-array case alternatives and native switch compilation remain unsupported.

- `debug.rs` provides source locations, a depth-aware DebugController and bounded, read-only frame snapshots. RuntimeHost checkpoints decide whether to stop and synchronously wait for debugger controls; the interpreter remains the owner of execution and scope. Script/function checkpoints run before instructions, with repeated loop-header checks. Caller previews are captured at call entry, function source/context is switched and restored on every return/error, and local variables never leak into the script environment. Inspection caps previews rather than cloning complete matrices.
- Session function definitions retain shared immutable DebugSource objects, including original source text, executable lines and UTF-16 editor columns. Studio binds source IDs to SHA-256(name + NUL + contents), verified in Electron main; older callers may use execution IDs. This keeps breakpoints independent of recent command history. The renderer maintains a separate 64-entry LRU text cache and opens read-only historical models when the editable document differs. A source-version mismatch is never corrected by overwriting the document.
- Persistent protocol v2 advertises capabilities including debugger. Execute accepts optional source_id/source_name and debug options; controls are debug_resume, debug_inspect, debug_pause and debug_breakpoints. Events are debug_source, debug_stopped, debug_frame, debug_resumed and debug_breakpoints. Every control/event is job-scoped; resume and inspection also carry the current pause_id, preventing stale commands from releasing later stops. Debug inspection is exempt from the 2 MiB cumulative program-output budget but retains an 8 MiB message cap, 1 MiB source cap, 33-frame cap, 100 variables per frame and 5x5 matrix previews. Invalid payloads still terminate an incompatible engine. Input pauses and debugger stops use separate controls. Cancellation wakes both and bypasses Sun catch.
- Monaco glyph-margin breakpoints, current-statement decorations and readonly debug execution/snapshot models are presentation only. Stack selection requests captured frame previews and cannot evaluate expressions. UI Run/Check/Reset remain single-flight while paused. Older engines without debugger capability retain ordinary execution and receive no new source/debug fields; unsupported debug requests produce a diagnostic without destroying session state.

- `graphics3d.rs` extends the existing figure effect with optional Scene3D data while leaving 2D traces unchanged. plot3 produces finite vertices and explicit disjoint line segments; matrix columns support multiple curves. surf validates vector/grid coordinates, triangulates finite nondegenerate cells, compacts unused vertices and computes bounds from surviving geometry. Area checks normalize each triangle locally by axis so isolated outliers and mixed axis magnitudes cannot discard valid cells. Limits are 16 curves/10,000 input points or 10,000 surface cells. FigureLayout adds Z label/range; axis validation requires six bounds for 3D. Source-of-truth geometry remains in Rust, and effects are forbidden in parfor/native compilation.
- FigureView dispatches 2D to Plotly and 3D to lazily loaded local Three.js with OrbitControls. The 3D renderer normalizes each axis to a cube for GPU precision, clips raw segments/triangles in double precision before Float32 conversion, renders finite surface geometry with height colors, and projects safe DOM labels. Numeric precision adapts to tick spacing and is shared with PNG annotations. Camera resets key off figure ID/axisRevision; unrelated metadata and resize preserve the camera. Updates render on demand; contexts, controls, geometries and materials are disposed on unmount. A composed PNG includes the WebGL image and metadata overlays. Headless tests use software WebGL and inspect framebuffer pixels plus camera changes, not only DOM existence.

- Graphics startup has an explicit automatic/software preference applied before app.ready, with launch-argument/environment/configuration precedence. Software opts into ANGLE/SwiftShader and Chromium's unsafe-swiftshader switch; the automatic default adds no flags and sandbox settings do not change. A trusted IPC action obtains native confirmation of security and session/unsaved-data loss, writes preferences atomically, shuts down the engine and relaunches with a single selected mode. Cancelling does not persist or restart. A failed 3D context can be recreated without replaying Sun source. Separate graphics tests reproduce a context failure, verify confirmation/cancellation, and render real pixels from a persisted preference without raw test-only GPU switches.

## Initial syntax

    A = [1, 2; 3, 4];
    B = A * A;
    C = A .* A;
    disp(B);
    disp(A(2, 1));

## Milestones

1. Lexer, source spans, AST and parser.
2. Interpreter execution for scalar expressions and matrix operations.
3. Packaging, installation scripts, and cross-platform release automation.
4. Semantic analysis and a stable Sun IR.
5. LLVM scalar expressions and native executable generation.
6. LLVM fixed-shape matrix code generation, matrix operations, display, and 1-based literal indexing.
7. Initial native C runtime ABI for math functions and self-contained executable linking.\n8. Heap-backed matrices, runtime matrix operations/indexing, element assignment, optimized kernels, user functions, control flow, JIT, and plotting.

## LLVM prerequisites

Install Clang/LLVM 18+ and ensure `clang` is on PATH, or set `SUN_CLANG` to the compiler executable. The Rust backend emits textual LLVM IR, so building the workspace does not require linking LLVM libraries.
